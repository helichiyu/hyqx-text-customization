二、入站认证拦截器需求（平台 → 算子服务）
----------------------------------------------------------------

原始需求：读取 work/common 里面的拦截器模块代码，
按其逻辑和内容给算子代码也加上拦截器模块。

运维反馈过一个问题：
    [WARN] 未设置 AUTH_TOKEN_SHA256/AUTH_TOKEN，认证拦截未启用
    （生产部署必须注入令牌，见规范 3.4）
结论：这是设计内的提示，不是报错——镜像里有拦截器，但容器没拿到
令牌环境变量，认证自动关闭。K8s 不像 docker compose 会自动读 .env，
Pod 环境变量必须由 Deployment 显式注入：

    env:
    - name: AUTH_TOKEN_SHA256
      value: ...

处理口径：
    服务只在集群内访问（测试）        可暂不处理
    通过 NodePort / Ingress 对外暴露  必须处理，否则等于裸奔
    平台侧还没配 X-Token             先别开，否则所有 /predict 会 401

数据合成产线实际使用的令牌与摘要：
    AUTH_TOKEN_SHA256=272b2f07afad843bca32b9d882477d7d5e3d6dd66367711bb1fbe2259ef1ff84
    对应原始令牌：dm55JugSxErtlLrvqq6lHihS_C04Mv0uyoQMJn2kmfQ
SHA-256 是单向摘要，不能从摘要反推原始令牌；调用方必须拿原始令牌。

四、补充：环境变量配置原则
----------------------------------------------------------------

为了以后方便修改，配置项不需要直接构建到镜像里或写死在代码里，
可以在启动的时候配置成环境变量，这样以后可以随时修改；
固定的环境变量可以直接写在镜像里面。

参考文件：
    anomalypattern.yaml                平台 K8s 部署清单（env: 段格式）
    ec678111770bb5bd73e4186aa4cd1.png  截图批注："非固定环境变量可以
                                       按照这种格式依次往后面添加"

即：固定变量写 Dockerfile ENV；非固定变量在 Deployment 的 env: 段
按 "- name: xxx / value: yyy" 格式按需添加，改完自动滚动重启生效，
不需要改代码、不需要重新构建镜像。
