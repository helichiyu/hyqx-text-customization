# 算子服务升级要求（供各产线参考）

> 适用范围：所有需要把算子服务接入平台认证、切换到 IDG/磐智模型网关、并按平台规范部署的产线。
> 本文档由数据合成产线的实际升级过程整理而来，需求出处见同目录《聊天记录.txt》（整理版）。
> 参考材料全部在本目录内，索引见文末第九节。

---

## 一、升级总览

升级包含两大改造点和一组部署规范：

| 模块 | 方向 | 内容 |
|---|---|---|
| 入站认证拦截器 | 平台 → 算子服务 | 请求头 `X-Token` 校验，服务端只存 SHA-256 摘要 |
| 模型网关客户端 | 算子服务 → IDG/磐智 | APPID+APPKEY 签名，模型按 PATH 区分，凭据走环境变量 |
| 部署规范 | — | 镜像命名、健康检查、环境变量分层、挂载策略、日志 |

核心原则（所有改造共同遵守）：

1. **配置与代码分离**：可变配置一律环境变量注入，不写死代码、不构建进镜像；改环境变量即生效，不需要改代码或重建镜像。
2. **固定变量进镜像，非固定变量启动时配**：固定的写 Dockerfile `ENV`，可变的在 K8s Deployment `env:` 段按需添加（格式见 `anomalypattern.yaml` 与 `ec678111770bb5bd73e4186aa4cd1.png`）。
3. **凭据不落盘**：APPKEY、令牌摘要等敏感值通过 Secret / 环境变量注入，不进代码、Git、日志和错误消息。

## 二、出站改造：调用 IDG/磐智模型网关

### 2.1 网关与凭据

- 网关：`http://10.252.92.98:9050`（通过 `MODEL_GATEWAY_BASE_URL` 配置）
- APPID / APPKEY 所有模型公用（见《聊天记录.txt》第一节），通过 `MODEL_APP_ID` / `MODEL_APP_KEY` 注入
- 模型由 **PATH 区分**，PATH 必须逐字使用模型清单的值，不能自行转换大小写或拼写
- 完整 PATH 清单见《聊天记录.txt》第一节；特殊映射：qwen3.8-27b → `/data-produce-1`

### 2.2 签名规则（参考 `qwen35_9b_call.py`、`idg_audio_call.py`、`deployment-kit/model_gateway/`）

```text
capability     = PATH 首段，右补 "0" 到 24 位
csid           = APPID + capability + uuid
X-Server-Param = base64(json({"appid": APPID, "csid": csid}))
X-CheckSum     = md5(APPKEY + X-CurTime + X-Server-Param)
```

请求头：`appKey`、`X-Server-Param`、`X-CurTime`、`X-CheckSum`。

### 2.3 模型选择（数据合成产线的实际映射，各产线按需对号）

| 用途 | 模型 | PATH | 说明 |
|---|---|---|---|
| 图像生成 | Longcat-Images | `/Longcat-Images` | 文生图与图生图共用同一 PATH，请求里有没有 `image` 决定模式 |
| 视频生成 | Wan2.1-I2v-14B-720P | `/Wan2.1-I2v-14B-720P` | 图生视频；纯文生视频无专用 PATH，复用该服务不带 `image` 请求 |
| 文本生成 | Qwen3.5-9B | `/Qwen3.5-9B` | 由较小的本地模型升级而来，选大一档的网关模型 |

### 2.4 输入模式要求（多模态算子）

同时兼容两种模式，不能只留一种：

- **只有文本**：纯文生图 / 文生视频；
- **图片 + 文字约束**：输入图作为参考（图生图 / 图生视频），文本照常传给模型约束生成。

实现口径：图片和文本在请求体里各自独立字段，有图带图、有文本带文本，两者都有时一并交给模型。代码里默认自带提示词，"只有图片没有文本"的情形可以不考虑。

### 2.5 其他调用要求

- Qwen3 系文本模型请求体加 `enable_thinking: false`，避免思考过程污染正文；
- 网关可能返回异步任务号而非直接产物：图像配 `IDG_IMAGE_STATUS_PATH`、视频配 `IDG_VIDEO_STATUS_PATH` 指向状态查询接口并轮询；响应解析要兼容直接二进制 / base64 / URL 三种形态；
- 校验响应头：`X-Code` 为空或 `1000000`，`X-IsSync` 不能为 `false`（异步任务接口除外）；
- 保留原有第三方后端（如 SiliconFlow）作为回退开关，通过环境变量切换，默认走 IDG。

## 三、入站改造：认证拦截器

参考实现：`work/common/auth_guard.py`（完整参考）、`deployment-kit/auth/`（含测试与接入示例）。

### 3.1 协议

- 调用方请求头携带 `X-Token: <原始令牌>`（兼容 `token` 头）；
- 服务端只保存令牌的 SHA-256 摘要：`AUTH_TOKEN_SHA256`（空格/逗号分隔支持多调用方）；
- `AUTH_TOKEN` 明文变量仅限本地联调，摘要变量优先；
- 比对用 `secrets.compare_digest` 防时序侧信道；不用 MD5。

### 3.2 行为

| 场景 | 行为 |
|---|---|
| `/health`、`/healthz`（含任意以 `/healthz` 结尾的算子探针路径） | 白名单放行，供 K8s/Docker 探针 |
| 其余路径缺少令牌 | 401 `{"code":1,"msg":"AUTH_MISSING..."}` |
| 令牌不符 | 403 |
| 认证启用时 `/docs` `/redoc` `/openapi.json` | 关闭 |
| `AUTH_DISABLED=1` | 显式关闭认证，仅限测试/本地，生产禁止 |

多算子统一服务形态：拦截器装在根应用上一次，挂载的子算子全部受保护，算子代码不感知。

### 3.3 令牌管理

- 摘要单向不可逆，调用方只拿原始令牌，服务端只配摘要；
- 找不回原始令牌时直接轮换：生成新令牌+摘要 → 服务端新旧摘要并用 → 更新调用方 → 验证正常 → 删旧摘要 → 重启；
- **各产线必须生成自己的令牌**，不要复用其他产线的；
- 健康检查不要用 `/openapi.json`（认证开启后会被拦截导致容器 unhealthy），一律用 `/healthz`。

### 3.4 K8s 注入（那个 WARN 的根因）

K8s 不像 docker compose 会自动读 `.env`，令牌必须由 Deployment 显式注入：

```yaml
env:
- name: AUTH_TOKEN_SHA256
  value: <sha256-digest>        # 或 valueFrom.secretKeyRef
```

未注入时服务打印 `[WARN] 未设置 AUTH_TOKEN_SHA256...` 并自动关闭认证——这是设计内提示，不是报错；但服务对外暴露或上生产时必须注入。

## 四、环境变量配置

### 4.1 分层原则

| 层 | 内容 | 修改方式 |
|---|---|---|
| 镜像内（Dockerfile `ENV`） | 固定变量：`PORT`、`WORKERS`、`OUTPUT_DIR`、`UPLOAD_DIR`、`PYTHONUNBUFFERED`、`PYTHONDONTWRITEBYTECODE`、`PYTHONPATH` 等 | 改 Dockerfile 重新构建（很少动） |
| 代码默认值 | 各后端 base_url、默认模型名、超时 | 不配置环境变量时兜底 |
| 启动时（Deployment `env:`） | 非固定变量：后端开关、凭据、模型覆盖、令牌 | 改 env 后自动滚动重启生效，**不改代码、不重建镜像** |

### 4.2 非固定环境变量清单（按需在 `env:` 段添加）

常用开关：

| 变量 | 默认 | 说明 |
|---|---|---|
| `IMAGE_GEN_BACKEND` | `idg` | 图像后端：`idg` / `siliconflow` / `openai_compatible` |
| `VIDEO_PROVIDER` | `idg` | 视频后端：`idg` / `siliconflow` / `comfyui` / `mock` |
| `SENTIMENT_MODEL_PROVIDER` | `idg` | 文本后端：`idg` / `local` |
| `SILICONFLOW_API_KEY` | 空 | 切第三方回退后端时必填 |

模型网关：

| 变量 | 默认 | 说明 |
|---|---|---|
| `MODEL_GATEWAY_BASE_URL` | `http://10.252.92.98:9050` | 网关地址变更时覆盖 |
| `MODEL_APP_ID` / `MODEL_APP_KEY` | 内置联调值 | 换正式凭据时覆盖，建议 Secret |
| `MODEL_GATEWAY_TIMEOUT_SECONDS` | `300` | 调用超时 |
| `MODEL_GATEWAY_RETRIES` | `2` | 重试次数 |

模型覆盖（PATH 类变量必须逐字照模型清单）：

| 变量 | 默认 |
|---|---|
| `IMAGE_MODEL` / `IMAGE_MODEL_PATH` | `Longcat-Images` / `/Longcat-Images` |
| `IDG_VIDEO_MODEL` / `IDG_VIDEO_MODEL_PATH` | `Wan2.1-I2v-14B-720P` / `/Wan2.1-I2v-14B-720P` |
| `SENTIMENT_MODEL` / `SENTIMENT_MODEL_PATH` | `Qwen3.5-9B` / `/Qwen3.5-9B` |

入站认证：`AUTH_TOKEN_SHA256`、`AUTH_TOKEN`（联调）、`AUTH_DISABLED`（测试）、`AUTH_WHITELIST_PATHS`（默认 `/health,/healthz`）。

异步任务：`IDG_IMAGE_STATUS_PATH` / `IDG_VIDEO_STATUS_PATH` 及对应轮询超时/间隔变量。

### 4.3 K8s 配置格式（照 `anomalypattern.yaml` / 截图批注）

```yaml
env:
- name: IMAGE_GEN_BACKEND
  value: idg
- name: VIDEO_PROVIDER
  value: idg
- name: AUTH_TOKEN_SHA256
  value: <摘要>
# 非固定环境变量按此格式依次往后面添加
```

敏感值（`MODEL_APP_KEY`、`SILICONFLOW_API_KEY`、`AUTH_TOKEN_SHA256`）建议 `secretKeyRef`。

### 4.4 切换即改值

- 切回退后端：开关值改 `siliconflow` + 填 `SILICONFLOW_API_KEY`；
- 切回磐智：开关值改回 `idg`（地址、凭据、模型都有默认值，不需要配）；
- 换凭据 / 轮换令牌 / 网关换址：只改对应变量。
所有切换均无需改代码、无需重建镜像。

## 五、部署与交付规范

1. **镜像与发布包命名**：全小写短横线，如 `oppretrain-cot-pool:1.0.0`、`oppretrain-sft-pool-v1.0.0.zip`；大写会直接构建失败（实测报错见 `68da026ed813e3c8f13f1b093963f27a.png`）。同一版本对应同一镜像，改代码必须换 tag。
2. **健康检查**：探针一律 `/healthz`（认证白名单内，无需令牌）；禁止用 `/openapi.json`。
3. **挂载策略（平台硬性要求：不在服务器上保存文件）**：
   - 部署清单**不挂载任何卷**：不用 PVC、hostPath、宿主机目录绑定，也不用 emptyDir——取消的就是"容器与服务器目录的连接"这一层；运行期文件（上传素材、生成成果、tempfile/ffmpeg 中间文件）只写在容器内部文件系统，随 Pod 删除自动回收，服务器上不留保存的文件；
   - **算子代码与镜像零改动**：算子照常读写 OUTPUT_DIR / UPLOAD_DIR（容器内路径），平台《算子输出格式要求》的 OUTPUT_DIR 落盘、`getOutputPath` 等规范接口照常成立；
   - 算子成果以 `/predict` 的 ZIP 响应流返回调用方（见 6.2），不依赖服务器上的文件；
   - resources 配 `ephemeral-storage` 限额：容器内部文件计入该项，视频拼接等中间文件较大，防超限被驱逐；
   - 备选加固：若平台连运行期占用节点磁盘都不允许，把 `/data/output`、`/data/uploads`、`/tmp` 换成内存卷 `emptyDir: {medium: Memory}` 即可，同样零代码改动。
4. **确需保存的文件构建进镜像，不做宿主机挂载**：平台口径"如果有文件要保存，直接写入镜像"——如本地模型权重构建期 COPY 进镜像（`INSTALL_TORCH_CPU=1` + COPY 权重目录）；默认全走模型网关时没有任何文件需要进镜像。
5. **日志**：INFO 级输出到容器标准输出（`PYTHONUNBUFFERED=1` 保证实时），`docker logs` / `kubectl logs` 查看；compose 配日志轮转（如 50MB×3）。日志应包含：算子装载结果、认证启用状态、每次生成的开始/成功/失败与耗时。
6. **发布流程与验收**：按 `deployment-kit/01_UPLOAD_AND_DEPLOY_FLOW.md` 执行（上传≠部署；构建成功≠服务可用；健康通过≠模型可调）。

## 六、算子功能要求

1. **多模态双模式**：见 2.4，输入图与文本都交给模型，两种模式都保留。
2. **成果随响应返回**：`/predict` 成功直接返回 ZIP 二进制流，调用方按 `Content-Type` 分支解析；失败返回 HTTP 200 + `{"code":1,"msg":"原因"}`。
3. **清理接口**：平台对文件清理有要求时需补齐——
   - 上传素材：`/removeFile?uniqueId=`（有 `/uploadFile` 的算子都应有）；
   - 生成成果：`/removeOutput`（按 runId）或 `/deleteOutput`（按 output_path）；
   - 数据合成产线的缺口（供对照自查）：金融流水、道路场景、混合特征三个结构化算子无成果清理接口；图像/视频算子只能清素材、清不了成果。平台按"不挂载"部署（成果不落服务器、随响应返回）时缺口可接受。
4. **生成过程临时文件自动清理**（拼接工作目录、临时打包文件等），无需调用方干预。

## 七、升级步骤清单

1. 从 `work/common/` 取 `auth_guard.py`（或 `deployment-kit/auth/`），接入服务入口：`FastAPI(..., **docs_off_kwargs())` + `install_auth(app)`；确认存在 `/healthz` 路由。
2. 引入模型网关客户端（签名逻辑参考 `qwen35_9b_call.py` / `deployment-kit/model_gateway/idg_signing_example.py`），凭据全部走环境变量。
3. 按模型清单为本产线算子选定 PATH，配好模型名/PATH 环境变量默认值；多模态算子实现图+文双模式。
4. 保留原有第三方后端为回退开关，默认走 IDG。
5. 整理环境变量分层：固定写 Dockerfile `ENV`，非固定在 Deployment `env:` 配置。
6. 按第五节规范调整 Dockerfile / compose / K8s 清单（命名、探针、零挂载、日志）。
7. 跑第八节验收。

## 八、验收清单

- [ ] `/healthz` 无令牌返回 200
- [ ] 业务接口无令牌 401、错令牌 403、正确令牌 200
- [ ] 认证启用后 `/docs`、`/openapi.json` 不可达
- [ ] 从**容器内部**验证模型网关可达、签名通过、目标 PATH 返回结构正确（文本出 `choices[0].message.content`；图像/视频出图/出片）
- [ ] 多模态算子两种输入模式（纯文本 / 图+文）各验一次
- [ ] 改 `env:` 后 Pod 滚动重启、新配置生效（`kubectl exec <pod> -- sh -c 'echo $...'` 核对）
- [ ] 部署清单无任何 volumes / volumeMounts（平台要求不在服务器保存文件）
- [ ] 日志实时可见、无敏感凭据明文
- [ ] 镜像/发布包名全小写、版本号规范
- [ ] 回滚方式已记录（保留旧镜像与旧清单）
