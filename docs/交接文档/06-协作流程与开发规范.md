# 协作流程与开发规范

## 1. Git 规范

- 禁止 `git reset --hard`、`git checkout --` 覆盖他人改动，禁止 rebase、stash 覆盖、force push。
- 合并远端：`git fetch` → `git pull --ff-only`，冲突时普通 merge 解决。
- 暂存必须逐个显式路径：禁止 `git add -A`、`git add .`、`git commit -a`。
- 提交信息格式：`类型（范围）：标题`，中文。
  - 示例：`修复（后训练）：完成PRE运行态与PostgreSQL验收`
  - 示例：`feat(pst)：接入四线算子池真实地址与X-Token鉴权`
- 一个提交只做一件事；文档、配置、代码尽量分开提交。

## 2. 禁止提交的本地内容

| 文件/内容 | 原因 |
| --- | --- |
| settings.xml（各仓库根目录） | 本地私服/镜像配置 |
| application.yml 本地改动（8081 端口、Jasypt NoIvGenerator 等） | 仅本地并行调试 |
| PstLocalAuthConfiguration.java | 本地绕权，默认 profile 不加载但不得入库 |
| PstJasyptCompatibilityContractTest.java | 本地兼容性测试 |
| .idea / .run / workspace.xml | IDE 配置 |
| pnpm-workspace.yaml 的 allowBuilds 占位符 | pnpm 11 自动生成，值为占位符，禁止提交 |
| 任何真实 Cookie、Authorization、账号密码 | 安全 |

## 3. 多窗口/多智能体协作方式

本项目长期使用“按系统分窗口”的协作方式（PST 窗口、Web 窗口、IND 窗口、PRE 窗口），每个窗口独立工作树、独立提交：

1. 每个窗口使用独立 git worktree（例如 `execution-run-prep`、`execution-b1`），避免互相覆盖。
2. 主工作树保留本地调试修改，不参与提交。
3. 契约变更（OpenAPI operationId、DTO、权限码）必须先由 PST 发布并推送，Web 窗口再通过 `git fetch` 检测并接线。
4. 每个窗口每完成一个阶段输出报告：改动文件、测试数、验证结果、遗留问题。
5. 长时间任务可在窗口内创建 pursuing goal，按阶段自动推进；同一外部阻塞连续三轮无法解决时标记 blocked 并说明缺什么。

## 4. 代码与文档风格

- 注释、OpenAPI 描述、文档统一中文（已在 PST 全线完成中文化）。
- 新增接口必须同步：Java 注解 → OpenAPI 快照 → Web 契约测试。
- 不在代码里写死真实内网地址或凭据（本次 X-Token 直写属负责人特批，后续新代码仍按环境变量注入优先）。
- 数据表变更必须新增 Liquibase changeSet，禁止修改历史 changeSet。
- 逻辑删除统一 `del_flag='F'/'T'`；雪花 ID 对外一律字符串化。

## 5. 构建与提交前检查

```powershell
git status --porcelain
mvn -B -s settings.xml "-DskipTests=false" clean package
git diff --check
```

Web：

```powershell
corepack pnpm vitest run <定向文件>
corepack pnpm vue-tsc --noEmit -p tsconfig.app.json --composite false
corepack pnpm eslint <定向文件>
corepack pnpm vite build
git diff --check
```

任一检查不过不得提交。

## 6. 与外部团队的协作口径

| 场景 | 口径 |
| --- | --- |
| 算子 tag/协议变更 | 必须算法组书面确认；未确认前不猜测映射 |
| K8s 网络/镜像 | 部署侧确认；PST 侧只记录 ENVIRONMENT_REQUIRED |
| PRE 契约缺口 | 以 Nexus 制品和 OpenAPI 为准，不以口头说明为准 |
| 真实 smoke | 无环境即跳过并标记，不用 mock 或 skip 冒充通过 |
| 发现共享基线测试失败 | 记录并移交对应团队，不擅自修复扩大范围 |

## 7. 交接后的第一步

1. 克隆三个仓库（地址见交接综述）。
2. 配置 JDK 21 + Maven 3.9.16 + Corepack pnpm 10.17.1。
3. 阅读 PST docs 目录关键文档：execution-run-orchestration、execution-run-smoke-runbook、execution-run-source-traceability、pst-known-issues、pst-pre-runtime-contract-gap-matrix。
4. 找运维/算法组确认阻塞清单（见遗留任务文档）。
5. 环境就绪后执行四线 smoke，产出真实联调证据。
