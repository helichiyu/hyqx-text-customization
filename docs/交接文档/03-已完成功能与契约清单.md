### 1.4 Execution B2B（execution/run）

契约：

```json
POST /hs-api/post-training-engine/prod/execution/run
请求：{ "taskId": "10001", "craftStep": 1 }
响应：{ "taskId": "10001", "craftStep": 1, "status": "STARTED" }
```

- operationId：`runPstProdExecution`；权限：`pst:prod:task:update`。
- taskId 为 1-19 位字符串形态数字；craftStep 必须存在于任务冻结快照。
- 同步返回 STARTED，实际异步执行。
- 线程模型：`pstProdExecExecutor`，核心 4 / 最大 4 / 队列 20 / CallerRunsPolicy（饱和时调用线程同步执行）。

幂等与并发（三层）：

1. 进程内 `runningStageKeys`（taskId:craftStep）防重；
2. 数据库活动记录检查（stage=EXECUTING AND end_time IS NULL AND del_flag=F）；
3. changeSet 033 生成列 + 唯一索引（`pst_active_execution_key`），解决多实例竞态；冲突转为业务冲突。

状态机约束：**run 不写任务状态/进度**；advance 仍是唯一状态推进入口。

执行落库：exec_log（逐算子开始/完成/ERROR/`__DONE__`）、stage_record 收口、operator_run 可信写入（旧代码只有读取方）、asset 落库。

失败语义：UNAVAILABLE / AUTH / BUSINESS_<code> / HTTP_<status> / PROTOCOL / TRANSPORT；失败记录可区分；服务重启后按活动记录自愈。
