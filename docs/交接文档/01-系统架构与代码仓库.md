# 系统架构与代码仓库

## 1. 系统边界

| 系统 | 职责 | 说明 |
| --- | --- | --- |
| PST 新框架（后训练） | 四线任务、资源、Execution 执行编排、资产、门禁、抽检、安全治理 | 本次交接的主体系统，独立仓库 |
| PRE 新框架（预训练） | 数据源、模板、产线、算子池、文件、执行等公共能力 | 通过 `hsmty-module-pre-client` Feign 制品对接 |
| Web 前端 | 后训练、预训练、平行语料、十一大行业页面 | Vue 3 + TypeScript + Vite |
| IND（十一大行业） | 行业数据集、行业算子编排与联合端点路由 | 独立仓库，Feign 契约已收口 |
| 旧整合工程 | 预训练 + 后训练的历史实现 | Gitee 仓库，是业务语义权威参考 |

## 2. PST 模块划分

| 模块 | 职责 |
| --- | --- |
| hsmty-module-pst-client | 对上游（PRE、OSS）的 Feign 客户端与 fallback |
| hsmty-module-pst-core | 业务核心：任务、资源、执行编排、资产、门禁、抽检、安全治理 |
| hsmty-module-pst-server | 服务打包与聚合 |
| hsmty-module-pst-start | Spring Boot 启动器（RunApplication）、配置、OpenAPI 发布 |

构建顺序：client → core → server → start，聚合根 `clean package` 一次完成。

## 3. 依赖栈与公共制品

| 组件 | 版本/约定 | 注意 |
| --- | --- | --- |
| JDK | 21（实测 21.0.12） | 编译与运行统一 JDK 21 |
| Maven | 3.9.16 | 建议使用项目自带 settings 或团队统一私服配置 |
| Spring Boot | 团队统一 BOM 管理 | 不单独锁定 Spring Cloud/OpenFeign 版本 |
| hsmty-common-feign | 2.0.1 | 提供 `FeignConfig`、`FeignResultDecoderConfig`（成功码 `0000`） |
| hsmty-common-security | 2.0.1 | 安全公共能力 |
| hsmty-module-pre-client | 2.0.1 | **直接返回业务对象**，共 27 个公开 Feign 方法；不再使用外层 `ApiResult` 包装 |
| hsmty-module-oss-client | 2.0.1 | `UploadFeignClient` / `DownloadFeignClient`，PST 文件上传下载统一走它 |
| spring-cloud-starter-openfeign | 5.0.2（BOM 决定） | 不显式写 4.x |
| feign-core | 13.6.1（BOM 决定） | 同上 |

重要历史教训：
- 旧 PRE 客户端曾使用 `ApiResult<T>` 包装和自定义 `PreFeignClientConfig` / `PreFeignApiResultDecoder`，这些类已从新制品中移除，**不得再引用**。
- 公司 Nexus 曾复用不可变版本号 `2.0.1` 覆盖制品内容，导致不同机器解析到不同 JAR。CI 应用空的 `maven.repo.local` 构建；发现签名不符时先核对制品 SHA-256。
- IND 的 Feign 接口仍保留 `ApiResult` 包装，因为 IND 服务端实际返回该结构，与 PST 不同，不要全局套用同一个 decoder。

## 4. 分支模型

| 分支 | 用途 |
| --- | --- |
| dev | 日常集成分支，所有功能先合入 dev |
| test | 测试环境发布分支，按需从 dev 普通合并 |

规则：
- 普通合并（`--no-ff` 或 fast-forward），禁止 force push、rebase、reset。
- 合并前先 `git fetch` + `git pull --ff-only`，确认远端基线。
- 提交信息使用中文规范格式：`类型（范围）：标题`，例如 `修复（后训练）：完成PRE运行态与PostgreSQL验收`。

## 5. 数据存储

| 项 | 说明 |
| --- | --- |
| 主数据库 | MySQL 8（与生产对齐）；本地可用 Docker MySQL 8 验证 |
| 兼容验证 | PostgreSQL 14.24 隔离容器全量跑通（Liquibase 45 个 changeSet，二轮 Run:0） |
| Schema 管理 | Liquibase，changeSet 必须二轮幂等 |
| 表命名 | canonical 表 `hs_pre_training_engine_*`（与 PRE 共享），逻辑删除 `del_flag` |
| 主键 | 雪花 ID，字符串化输出（大于 JS 安全整数） |
| 执行唯一约束 | changeSet 033：生成列 + 唯一索引，保证同一任务同时最多一条活动 EXECUTING 记录 |

禁止将 PST Liquibase 直接指向共享 `idg_db` 执行全量 changeSet；必须使用专用库或测试库。

## 6. OpenAPI 与冻结契约

- 当前 origin/dev：28 份 OpenAPI、202 个唯一 operation（实测）。
- 历史审计：Web 侧 180 个 method + path 与 PST 180 个 operation 完全匹配，0 缺失、0 不一致。
- 四线生产接口共 16 个（含 5 个 Execution 只读 + run 等），PCT 契约 180 个保持冻结。
- 新增接口必须同步：Java 注解 → OpenAPI 生成 → 静态快照 → Web 契约测试。
- `execution/run` 的 operationId 为 `runPstProdExecution`，允许状态 `STARTED`，权限 `pst:prod:task:update`。

## 7. 关键业务概念

| 概念 | 说明 |
| --- | --- |
| 四线 | SFT、RLHF、REASONING（CoT）、EVAL |
| craftStep | 工艺树环节序号；run 以 taskId + craftStep 定位 |
| 模板快照 | 任务创建时冻结模板，执行只读快照，不回查模板最新版 |
| advance | 唯一任务状态推进入口；run 本身不写任务状态 |
| 人工节点 | RLHF/CoT/EVAL 部分环节需人工处理，执行会在人工节点暂停 |
| 资产 | 执行产物通过 execution/asset 查询，文件字节存 OSS |
