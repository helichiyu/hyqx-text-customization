# 部署问题排查与处理

> 适用系统：PRE、PST、Web、IND 及 K8s 算子池
>
> 基线日期：2026-11-12
>
> 本文按“现象 -> 根因 -> 处理 -> 验证”整理实际遇到过的部署和联调问题。
> 凭据、Cookie、Authorization、Token 和密码不得写入本文，也不得提交到 Git。

## 1. 快速排查表

| 现象 | 常见根因 | 优先处理 |
| --- | --- | --- |
| `Port 8080 was already in use` | PRE 和 PST 同时使用 8080 | PRE 8080，PST 8081；端口只通过本地启动参数覆盖 |
| `PRE service url is not configured` | PST 的 `pre.service.url` 为空 | 配置 `PRE_SERVICE_URL` 或启动参数，并启动 PRE |
| PRE 接口返回 302，跳转 SSO | PRE 未启用本地鉴权或未加载 `local` profile | 本地使用 `PreLocalAuthConfiguration`，重建并以 `local` 启动 |
| PST 返回 503 / C2001 | PRE 返回 302、5xx 或连接失败 | 先修 PRE，不修改 PST 业务代码 |
| `downloadFile` 返回 404 | CoT 当前镜像没有下载路由 | 换用带 `/downloadFile` 的修复版镜像 |
| T05 出现 `Empty reply from server`，reject 文件写 `MODEL_GATEWAY_BASE_URL` 未配置 | SFT 算子缺少模型网关配置 | 由算法组提供网关地址，通过 K8s Secret/Deployment 注入 |
| 页面请求资源不存在 | 前后端路径、代理目标或部署版本不一致 | 核对 Vite 代理、Ingress、Service 和实际 Pod |
| Web 页面访问 PRE 仍跳 SSO | Vite 代理指向了未经本地绕权的 PRE | 核对 `VITE_API_PROXY_TARGET` 和专用代理顺序 |
| `pnpm-workspace.yaml` 出现 `set this to true or false` | pnpm 11 自动迁移 `allowBuilds` | 固定 Corepack pnpm 10.17.1，禁止提交占位值 |
| 本地编译报 `com.hsmty.pre.feign.config` 不存在 | 仍在使用旧 PRE Feign 包装契约 | 使用新 `pre-client:2.0.1` 直返业务对象契约 |
| 不同机器同一 `2.0.1` 编译结果不同 | Nexus 复用版本号覆盖制品或本地缓存过期 | 使用空 Maven 仓库复核，校验 SHA-256，推动不可变版本 |

## 3. 本地启动与常见错误

### 3.1 PRE/PST 端口冲突

现象：

```text
Web server failed to start. Port 8080 was already in use.
```

根因：PRE 和 PST 同时使用 8080。

处理：

1. `8080` 留给 PRE。
2. PST 使用 `--server.port=8081`。
3. 不要为了本地并行而修改并提交 `application.yml` 的默认端口。

IDA/PST 启动参数至少包含：

```text
--spring.profiles.active=local
--server.port=8081
--pst.service.url=http://127.0.0.1:8081/hs-api/post-training-engine
--pre.service.url=http://127.0.0.1:8080/hs-api/pre
--oss.service.url=http://127.0.0.1:8080/hs-api/pre
```

`pre.service.url` 必须包含 `/hs-api/pre`，否则 Feign 请求会少一层路径。

### 3.2 `PRE service url is not configured`

现象：创建强化学习任务时，原始数据集和生产模板加载失败。

根因：

- PST 的 `pre.service.url` 为空；
- 或 `PRE_SERVICE_URL` 没有注入；
- 或 PRE 没有启动。

验证：

```powershell
Invoke-WebRequest `
  -Uri 'http://127.0.0.1:8080/hs-api/pre/task/stages' `
  -MaximumRedirection 0 `
  -TimeoutSec 10
```

要求返回 HTTP 200。若返回 302，继续看下一节。

### 3.3 PRE 本地接口返回 302

正式 PRE 走 SSO，无 Cookie 时返回 302 是正常行为。
本地联调要使用仅在 `local` profile 生效的 `PreLocalAuthConfiguration`：

```text
D:\HYQX\pre\hsmty-module-pre-start\src\main\java\com\hsmty\configuration\PreLocalAuthConfiguration.java
```

该配置：

- `@Profile("local")`；
- 放行本地 `/pre/**`；
- 注入用户 ID `1`，供审计字段使用；
- 只用于本地联调，不能提交。

处理顺序：

1. 确认 8080 是从 `D:\HYQX\pre` 启动的 PRE，不是另一个工作树或旧 JAR。
2. Build/Rebuild，确认以下 class 存在且为新时间戳：

```text
D:\HYQX\pre\hsmty-module-pre-start\target\classes\com\hsmty\configuration\PreLocalAuthConfiguration.class
```

3. 使用以下参数重启：

```text
--server.port=8080 --spring.profiles.active=local
```

4. 启动日志必须包含：

```text
The following 1 profile is active: "local"
```

5. 无 Cookie 访问 PRE 接口，必须返回 200，不能跳 SSO。

如果 profile、class 和进程都正确但仍 302，才检查本地 `PreLocalAuthConfiguration` 与当前安全链路的匹配关系；不要修改公共安全模块来给本地开口。

### 3.4 PST 出现 503 / C2001

这是 PST 对 PRE 下游失败的包装，不一定是 PST 本身故障。

排查顺序：

1. 直接请求 PRE 接口，确认是否为 200。
2. 检查 PST 日志中的 Feign 请求地址是否含 `/hs-api/pre`。
3. 检查 PRE 是否返回 302、401、403、5xx 或连接拒绝。
4. 修复 PRE 后再重测 PST。

不要通过修改 PST 状态码或增加 mock 来掩盖 PRE 未启动。

### 3.5 Web 代理错误

Vite 只在启动时读取代理环境变量，修改后必须重启。

本地常用目标：

```text
/hs-api/pre/**                 -> http://127.0.0.1:8080
/hs-api/post-training-engine/** -> http://127.0.0.1:8081
```

如果专用规则放在通用 `/hs-api` 规则后面，可能被通用规则覆盖，导致 302 或证书错误。专用路径必须优先匹配。

Vite 代理配置只保留在工作树本地，不提交。

## 4. 构建、Feign 与 Nexus 问题

### 4.1 PRE Feign 契约已改为直接返回业务对象

当前 `hsmty-module-pre-client:2.0.1`：

- 五个 Feign 接口直接返回业务对象；
- 不再返回 PST 自定义的 `ApiResult<T>` 外层；
- 不再提供旧 `PreFeignClientConfig`、`PreFeignApiResultDecoder`、`PreFeignBizException`；
- PST 使用公共 `FeignConfig` 和 `FeignResultDecoderConfig`。

如果编译出现：

```text
package com.hsmty.pre.feign.config does not exist
```

说明仍在使用旧协议或本地缓存了旧制品。处理：

1. 删除或备份旧 `hsmty-module-pre-client\2.0.1` 目录；
2. 重新从公司 Nexus 拉取；
3. 检查 JAR 中不存在旧 config 包；
4. 删除 PST 中旧的 `PreApiResult`、`PreResponseGuard` 等包装代码；
5. 重新聚合构建。

不要为了消除编译错误而自行复制旧 `config` 类到项目中。

### 4.2 IND 与 PST 的返回契约不同

- PST/PRE：Feign 直返业务对象，公共 decoder 成功码为 `0000`。
- IND：服务端实际仍返回 `ApiResult<List<IndVO>>`，客户端必须保留包装。

不要把同一个全局 decoder 无差别套到所有 Feign 客户端。

### 4.3 Nexus 复用 `2.0.1` 版本号

历史故障：同一坐标 `pre-client:2.0.1` 在不同机器解析到不同 JAR，甚至出现过缺少 config 包、大小和 SHA 不同的情况。

处理原则：

1. 不要只执行普通 `mvn -U` 就认为缓存已彻底刷新。
2. 使用全新的临时 Maven 仓库构建：

```powershell
mvn -B -s settings.xml `
  -Dmaven.repo.local=C:\temp\empty-maven-repo `
  "-DskipTests=false" clean package
```

3. 记录关键制品的大小和 SHA-256。
4. 依赖树确认没有旧版本和 `pre-core`/`pre-start` 混入。
5. 如果 nexus 上的同版本内容发生变化，按发布事故处理：
   - 先备份当前 artifact 目录；
   - 保存新旧 SHA；
   - 通知公共制品负责人；
   - 优先推动发布新的不可变版本号。

### 4.4 OpenFeign 版本

不要单独锁定 OpenFeign 4.x。使用团队 BOM 管理的版本。
历史上 `spring-cloud-starter-openfeign:5.0.2` 与 `feign-core:13.6.1` 是已验证组合。

### 4.5 文件上传下载

PST 公共文件链路使用 `hsmty-module-oss-client:2.0.1`：

- 上传：`UploadFeignClient` / `UploadDTO`
- 下载：`DownloadFeignClient`

不要重新引入 PST 私有的 OSS DTO 或自行拼接 PRE 文件接口。
`OSS_SERVICE_URL` 为空时应用应能启动，但上传/下载调用应稳定返回 `UNAVAILABLE`，不能阻塞启动。

## 5. 数据库与 Liquibase

### 5.1 禁止直接对共享库执行 PST 全量迁移

不允许直接把 PST Liquibase 指向共享 `idg_db`。应使用专用本地或测试库。

### 5.2 本地 `pst_dev` 缺少 PRE 共享表

现象：

```text
hs_pre_training_engine_stage_record 表不存在
Liquibase 033 被 MARK_RAN
```

根因：只执行了 PST 表迁移，没有 PRE 侧共享表。

处理原则：

1. 先对 `pst_dev` 做完整 SQL 备份。
2. 使用同版本 PRE 包对专用库创建共享表。
3. 检查 `databasechangelog` 中 033 的状态。
4. 只有在表结构齐备且已备份时才重跑 033。
5. 确认 033 的生成列和唯一索引真实存在。

已验证的本地结果：

- PST 表约 39 张；
- PRE 共享表约 28 张；
- 合计约 69 张；
- MySQL 8 下重复活动 `EXECUTING` 插入会触发 1062；
- 二轮 Liquibase 应为 `Run: 0`。

不要通过修改历史 changeSet 来解决本地表缺失。

### 5.3 与 PRE 共库的风险

共享 canonical 表意味着 PST 和 PRE 表结构必须来自同一版本。
如果版本不一致，优先拆分专用库或由平台统一发布数据库版本，不要手工长期维护两套结构。

检查命令：

kubectl -n obu-ai-cloud describe deploy <name>

### 6.2 合并部署路线 A

负责人已确定采用路线 A：维持合并部署，不长期保留 IND 独立 Deployment。

已知事实：

- IND 独立 Deployment 是临时方案；
- `hsmty-corpus-server` 镜像曾确认包含新 IND 代码；
- 收回 IND 时优先调整 ConfigMap、Secret 和 Ingress，不重复构建业务代码；
- PST 合并部署需要先把 PST core/client 制品发布到 Nexus，再由 Jenkins 重建 `hsmty-corpus-server`；
- 合并后必须注入 `pst:*` 配置、PRE/OSS 地址和 Secret；
- 必须对专用库执行 PST Liquibase，不能直接操作共享库；
- 部署后验证 `/hs-api/post-training-engine/**`、`/hs-api/pre/**`、`/hs-api/industry-dataset/**` 路由。

发布前检查：

1. Nexus 上的 PST 制品是否包含当前版本的 execution/run 类。
2. Maven 缓存是否可能解析到旧 JAR。
3. Jenkins 是否使用干净构建或明确记录依赖 SHA。
4. ConfigMap 是否包含 `pre.service.url`、`oss.service.url` 和四线地址。
5. Secret 是否注入 X-Token、模型网关密钥等敏感值。
6. 数据库 changeSet 是否已执行且二轮幂等。
7. Ingress 是否仍指向正确的 Service。

### 6.3 SFT T05 模型网关缺失

现象：

- T05 health 正常；
- 真实种子处理后出现连接关闭或 `Empty reply from server`；
- 算子输出目录中的 `fewshot_rejects.jsonl` 明确记录：

```text
大模型调用失败（重试 2 次后）：模型接口地址未配置：MODEL_GATEWAY_BASE_URL
```

已确认当前 K8s SFT 镜像为 `oppretrain-sft-pool:1.0.0`，Pod 没有模型网关环境变量。

需要使用 K8s Secret/ConfigMap 注入类似配置：

```text
MODEL_PROTOCOL=panzhi
MODEL_GATEWAY_BASE_URL=<由算法组提供>
MODEL_APP_ID=<由算法组提供>
MODEL_APP_KEY=<通过 Secret 注入>
```

如果使用 OpenAI 兼容协议，则还要配置：

```text
MODEL_PROTOCOL=openai
SFT_FEWSHOT_API_BASE=<OpenAI 兼容地址>
SFT_FEWSHOT_API_KEY=<通过 Secret 注入>
SFT_FEWSHOT_API_MODEL=<模型 ID>
```

验收：

1. Pod 内环境变量存在且密钥不打印到日志；
2. T05 不再产生 `MODEL_GATEWAY_BASE_URL` 缺失；
3. 单条种子能产生 few-shot 草稿；
4. 完整 SFT 链路能从 STARTED 到 DONE；
5. 产物落库并可下载。

不要把真实密钥写入 `application.yml`、ConfigMap 明文或交接文档。
`192.168.1.105` 上的旧容器只作为版本比对，不是正式部署基线。

### 6.4 CoT 缺少 downloadFile

现象：

```text
predict 成功
GET /PTI-Reason_assess_difficulty/downloadFile?path=... -> 404
```

已确认当前 K8s CoT 镜像 `oppretrain-cot-pool:1.0.0` 的协议只实现：

```text
/healthz
/uploadFile
/predict
/removeFile
/prefill
```

没有 `/downloadFile`。`predict` 只返回容器内 `outputFile` 路径，PST 无法直接读取另一个 Pod 的路径。

处理：

1. 算法组提供包含 `/downloadFile` 的修复版镜像；
2. 记录镜像 tag、commit SHA、manifest digest；
3. 部署后用不存在的路径探测，返回业务 `FILE_NOT_FOUND` 说明路由存在；返回 FastAPI `Not Found` 说明路由仍缺失；
4. 再执行完整 CoT 链，验证 `predict -> downloadFile -> asset`。

`192.168.1.105:17009` 的旧 Docker 容器曾验证包含下载路由，但它是旧实例，不代表当前 K8s 镜像；不能直接把旧容器地址写死为生产配置。

### 6.5 算子 Service 与 Pod IP

严禁把 Pod IP 写死到 PST/PRE/IND 配置中。

正确调用：

```text
集群内：
  http://oppretrainsftpool:17054
  http://oppretrainrlpool:17055
  http://oppretraincotpool:17056
  http://oppretrainevalpool:17057

本地工作站：
  通过 pst-op-proxy NodePort 30054-30057
```

Pod 重启后 IP 会变；Service DNS 和 NodePort 才能保持稳定。

## 7. 四线真实联调检查清单

### 7.1 环境

- PRE 8080 返回 200；
- PST 8081 返回 200；
- Web 9849 页面可打开；
- NodePort 30054-30057 可达；
- PST 日志中的算子地址与代理目标一致；
- 不使用旧 `.105:17007/17009` 冒充当前 K8s 池。

### 7.2 逐线验证

| 产线 | 已验证状态 | 仍需条件 |
| --- | --- | --- |
| RLHF | 真实算子成功，stage DONE，operator_run SUCCESS，资产可下载 | 保留测试任务证据 |
| EVAL | 两个算子真实成功，资产可下载 | 保留测试任务证据 |
| SFT | T03/最小链路成功；完整模板受 T05 模型配置阻塞 | 模型网关配置 + 完整任务重测 |
| CoT | 三个 predict 成功；下载路由 404 | 修复版镜像 + 完整链重测 |
| Web | RLHF 页面启动执行、轮询、日志、资产已验证 | 四线完整链路受后端外部条件影响 |

### 7.3 通过标准

- 每线至少一次真实执行从 STARTED 到 DONE；
- 数据库有任务、阶段记录、operator_run、exec_log；
- operator_run 有 SUCCESS、cost/rows 或等价证据；
- asset 有 ossId/lineageRef，下载成功；
- 无 401/403/302 被误判为业务成功；
- 没有用 mock、跳过测试或伪造阶段记录替代真实 smoke。

## 8. 故障处理边界

| 层级 | 常见责任 |
| --- | --- |
| PST、Web 代码 | 接口契约、代理接线、轮询、状态展示、执行编排 |
| PRE | SSO、本地绕权、数据集/模板接口、公共任务契约 |
| 算法/算子组 | SFT/RLHF/CoT/EVAL 算子镜像、模型网关、下载路由、算子行为 |
| K8s/运维 | Deployment、Service、Ingress、ConfigMap、Secret、DNS、NetworkPolicy |
| 业务/数据 | 数据集授权、模板发布、测试 ID、人工节点口径 |

处理原则：

1. 先用实际接口、Pod 日志和 OpenAPI 定位层级。
2. 不把 PRE 的 302 当成 PST 业务错误。
3. 不把算子镜像缺失当成 PST 客户端 bug。
4. 不用修改公共鉴权或跳过真实 smoke 来“通过”。
5. 外部阻塞写清缺失字段、提供方和验证方式。
