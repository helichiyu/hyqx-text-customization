### 32.1 ID 生成规范（全站统一，禁止各组自创）
平台对象（任务、数据集、策略、算子、配置、模型…）的 ID 分**三层**，各有用途，不允许混用或自创格式。

**第一层：内部主键（系统内部，不对外）**

+ 算法：**雪花算法 Snowflake**，19 位长整型（如 2074457061897732097）。
+ 特点：全局唯一、趋势递增、分布式可用、按时间有序。
+ 用途：数据库主键、内部表关联。
+ **不直接暴露在对外 URL / 分享链接中**（避免业务量被推算、记录被遍历）。

**第二层：业务编号（用户可见、可搜索、可口头沟通）**

+ 格式：业务前缀 + 日期 + 随机码
+ 结构：前缀(2–4 位大写字母) + yyMMdd(6 位) + 6 位随机码，总长 **14–16 位**。
+ 示例：TASK261026A3F9KX、DS261026K7M2PQ。
+ 随机码字符集：去掉易混淆的 0/O、1/I/L，只保留 31 个安全字符（数字 2–9 + 大写字母除 I/L/O），用**密码学安全随机（CSPRNG）**生成，不用普通 rand()。
+ 容量：单日单类型可承载万级（6 位随机空间约 8.8 亿，日产量超万的对象随机位加到 8 位）。

**第三层：语义化编码（程序对接，稳定不变）**

+ 用于程序调用、接口对接，需稳定、可读，如算子调用编号 042t_education_discrimination。
+ 规则：小写字母 + 数字 + 下划线，模块前缀_英文语义，一旦发布不可更改。

**ID 安全铁律**：

1. **对外禁止用自增 ID（1,2,3…）**——会暴露总量、可被逐条遍历抓取。
2. 对外 / 分享 ID 必须**无规律、不可预测、不可枚举**。
3. ID 中**不含任何敏感信息**（手机号、身份证、姓名、邮箱、单位名）。
4. 随机数必须用**密码学安全随机**；长度、前缀、格式全站统一。
5. 业务编号一律 **monospace 等宽字体展示**，可一键复制；不在 ID 里加空格或特殊符号。
