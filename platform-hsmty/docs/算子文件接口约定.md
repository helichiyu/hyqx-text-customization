# 算子文件与进度接口约定

> 适用范围：文本定制化生产平台（`tcs`）对接的四条产线共 11 个算子。
> 平台与算子**不在同一服务器**，算子运行在独立容器/主机，平台不挂载共享目录，产物与进度全部通过 HTTP 获取。
> 平台侧实现见 `hsmty-module-tcs-core/src/main/java/com/hsmty/tcs/operator/HttpOperatorFileService.java`
> 与 `OperatorClient.java`；算子地址由 `tcs.operator.base-url` + `tcs.operator.ports` 决定。

---

## 1. 已依赖的算子接口（现状）

平台按算子链依次调用，除 `/predict` 外，还依赖下列基础接口：

| 方法   | 路径                | 说明                                             |
| ---- | ----------------- | ---------------------------------------------- |
| GET  | `/healthz`        | 健康检查，HTTP 200 即视为可用                            |
| POST | `/uploadFile`     | `multipart/form-data`，字段 `file`；query `uniqueId`；上传素材 zip |
| POST | `/predict`        | 长任务（超时 1800s），JSON 请求体，返回 `data` 对象             |
| POST | `/removeFile`     | query `uniqueId`；幂等清理素材                         |

`/predict` 响应 `data` 至少包含：

```json
{
  "outputFile": "/output/xxx/result.json",
  "summary": {},
  "skipped": [],
  "failed": []
}
```

- `outputFile` 是**算子视角的绝对或相对路径**，平台会原样作为后续 `/listFiles`、`/downloadFile` 的 `path` 参数回传，算子不得对该路径做二次解释或拼接。
- `summary` / `skipped` / `failed` 原样入库，用于质量报告与编排状态。

## 2. 新增：产物读取接口（平台 → 算子）

平台在以下场景调用：

1. 任务详情页「产物文件」抽屉：列出某次运行的输出文件；
2. 复核工作台左侧「原始素材 / 来源内容」预览：按文件名读取图片或 JSON；
3. 结果核对与数据集预览：读取 `outputFile` 指向的结构化结果。

### 2.1 列出文件

```
GET /listFiles?path={outputFile}
```

- `path`：`/predict` 返回的 `outputFile`，URL-encoded。
- 成功响应（HTTP 200）：

```json
{
  "code": 0,
  "msg": "ok",
  "data": [
    { "name": "result.json", "size": 20480 },
    { "name": "page_001.png", "size": 153600 }
  ]
}
```

要求：

- `code` 必须为 `0`；非 0 时平台按业务失败抛出 `msg`。
- `data` 为数组；元素至少提供 `name`（文件名，不含目录）与 `size`（字节数，数字）。
- 只返回**该次运行输出目录下的一层文件**；平台不做递归遍历。
- 文件不存在或目录为空时返回 `data: []`，不要返回 4xx/5xx。

### 2.2 下载文件

```
GET /downloadFile?path={outputFile}&name={fileName}
```

- `path`、`name` 均为 URL-encoded；`name` 必须来自 `/listFiles` 的返回。
- 成功：HTTP 200，响应体为**原始文件字节**（`Content-Type` 按文件类型设置，如 `application/json`、`image/png`）。
- 失败：HTTP 非 200 时，平台把响应体前 300 字节作为错误信息展示。
- 平台对单文件读取超时为 600s，大文件请直接流式返回。

### 2.3 运行进度（可选，缺失时平台自动降级）

```
GET /progress?runId={progressKey}
```

- `progressKey` 由平台在 `/predict` 请求体中传入，值为平台 `task_stage_run` 主键（字符串）。
- 成功响应：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "percent": 42,
    "stage": "ocr",
    "message": "正在识别第 42/100 页"
  }
}
```

要求：

- `data` 为对象，字段可自由扩展，平台原样存入 `stage_run.progress` 并透传给前端；
- 未实现或读取失败时返回非 0 / 非 200 即可，平台记录 debug 日志后忽略，不影响任务执行；
- 建议以 `runId` 为键落盘或放内存，任务结束后可保留一段时间便于排查。

## 3. `/predict` 请求体字段（平台已发送）

平台按算子链构造请求体，算子只需读取自己认识的键：

| 字段                      | 出现条件                 | 说明                                        |
| ----------------------- | -------------------- | ----------------------------------------- |
| `uniqueId`              | 阶段首个算子               | `{任务id}_{素材批次id}`，与 `/uploadFile` 一致      |
| `inputFile`             | 中段算子                 | 上一环节 `/predict` 返回的 `outputFile`，原样透传     |
| `isLastOperator`        | 链尾算子                 | `true` 表示该环节输出即数据集来源                      |
| `progressKey`           | 每次 `/predict`        | 本次运行 ID，用于 `/progress?runId=`             |
| `category`              | 仅 `img_type_classify` | 图文大类（几何/统计/表格/示意）                         |
| `confidence_threshold`  | 算子支持时                | 任务级阈值（0–1）                                |
| 其它参数                    | 算子支持时                | 来自产线参数快照，按 `TAG_PARAMS` 白名单透传，区间值取下界      |

## 4. 平台侧配置

```yaml
tcs:
  operator:
    file-mode: http          # http（默认，走上述接口）/ local（本地联调，读共享目录）
    base-url: http://...     # 算子主机基地址
    deployment: per-port     # per-port（默认，每算子独立端口）/ shared-port（合并容器，单端口 + 路径前缀）
    shared-port: 17022       # 仅 shared-port 生效
    ports:                   # 与算子 tag 一一对应
      meta_clean_slice: 6301
      # ...
    runtime-dir: ...         # 仅 file-mode=local 时使用
```

- `deployment=per-port`：算子地址为 `{base-url}:{ports[tag]}`，对应 `operators/docker-compose.yml` 的 11 服务形态。
- `deployment=shared-port`：11 个算子合并为单容器，算子地址为 `{base-url}:{shared-port}/{tag}`，例如
  `http://算子主机:17022/meta_clean_slice`；对应 `operators/_deploy/docker-compose.yml`（服务名 `op-custom-text`）。
- `file-mode=http` 时平台**不读取任何本地目录**，`/listFiles`、`/downloadFile`、`/progress` 必须可用。
- 联调可临时设 `TCS_OPERATOR_FILE_MODE=local`，此时产物读取走平台本地 `runtime-dir`，不校验上述接口。

## 5. 联调自检清单

- [ ] `curl "{算子地址}/healthz"` 返回 200
- [ ] `/predict` 返回 `data.outputFile`，且该路径可被 `/listFiles?path=` 直接使用
- [ ] `/listFiles` 返回 `{code:0,data:[{name,size}]}`
- [ ] `/downloadFile?path=&name=` 返回文件字节，JSON/PNG 可正常打开
- [ ] `/progress?runId=` 返回 `{code:0,data:{...}}`，10s 内响应
- [ ] 路径含中文、空格时，算子能正确按 URL-decoded 值定位文件
