# 旧版功能对齐核对（wbdz → tcs）

> 核对日期：2026-11-11
> 对照对象：旧版 `platform/wbdz-web` + `platform/wbdz-server`，新版 `platform-hsmty/tcs-web` + `platform-hsmty/tcs-server`。
> 目的：按“前后端已联调好的业务行为完整复刻”的要求，逐页、逐接口确认没有功能丢失。

---

## 1. 核对方法

- 前端：对 6 个页面、4 个公共组件、布局/路由/页签做逐行对照，列出旧版每个可见元素、交互、校验提示、确认框文案和 API 调用，再在新版中逐项定位。
- 后端：对照 Controller 路由、DTO/VO 字段、Service 业务规则；用脚本比对全部 DTO/VO 字段集合。
- 只把“用户可感知的业务行为”算作差异；CSS 变量、类名前缀、代码格式不计。

### 2.1 前端有意差异

| 项 | 旧版 | 新版 | 原因 |
| --- | --- | --- | --- |
| 路由前缀 | `/wb/:line`、`/task/:bizNo` 等 | `/custom-text/wb/:line`、`/custom-text/task/:taskRef` | 作为 qiankun 子应用，避免与主应用路由冲突；页内跳转已全部同步 |
| 接口前缀/信封 | `/api/...`、`{code:number,msg,data}` | `/hs-api/tcs/...`、`{code:"0000",message,data}` | HSMTY 统一网关前缀与返回结构 |
| 分页 | `pageNum/pageSize`、`records` | `page/limit`、`rows` | HSMTY `PageQuery` / `PageResult` |
| 登录页 | `/login` + JWT localStorage | 无独立登录页，由主应用 UAP/SSO 下发用户 | 见第 4 节；需甲方确认本地放行方式 |
| 401 处理 | 清 Token 并跳 `/login` | 提示“登录状态已失效”并派发 `hsmty:unauthorized` 事件，由宿主处理 | 子应用不持有登录态，不自行跳转 |
| 任务路由参数名 | `:bizNo` | `:taskRef` | 参数同时接受 ID 与业务编号，名称与后端 `reference` 对齐 |

## 3. 接口对照

### 3.2 字段核对

脚本比对结果：旧版全部业务 DTO/VO 的字段在新版中均存在；仅 `LoginDTO`、`LoginVO`、`CurrentUserVO`、`HealthVO` 因认证方案变化未保留（健康检查改为无数据体的统一响应）。

### 3.3 初始数据

旧版 `DataSeeder` 会在启动时写入 admin 账号和 5 份初始参数版本（四条产线 + 公共规则）。新版：

- admin 账号不再需要（SSO 接管）；
- 5 份初始参数版本已改为 Liquibase `014_tcs_param_version_seed.xml`，按 `line` 幂等写入，避免新库为空时“任务创建无已发布参数版本”。

## 4. 唯一未复刻项：登录

旧版为 `Login.vue` + JWT（`localStorage['wbdz_token']`）+ `/api/auth/login`、`/api/auth/me`。新版按技术选型文档改为 **UAP/SSO Cookie + Spring Security `@PreAuthorize`**：

- 子应用不保存 Token，用户与权限由主应用经 qiankun props 下发；
- 后端未接入 UAP 时，未登录访问业务接口返回 `302`；
- 本地放行会关闭鉴权，属于安全变更，需用户显式授权（DECISIONS Q-007），当前未实现。

如确需在本地完整复刻旧版登录体验，需要先确认：是否接受在 `local` profile 下引入独立的本地登录（与 UAP/SSO 方案并行），以及本地账号来源。生产环境仍以 UAP/SSO 为准。

## 5. 仍需外部提供

1. UAP/SSO 校验地址、跳转地址、Cookie 名称，以及本地是否放行。
2. 菜单/权限码号段：`@PreAuthorize` 已使用 `tcs:{resource}:{action}`，需要在菜单体系中授予对应权限，否则接口返回 403。
3. 算子侧三个文件接口（`/listFiles`、`/downloadFile`、`/progress`）的实现与联调。
4. 生产库、Redis、OSS 参数。
