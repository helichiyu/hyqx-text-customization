## 实施方案

1. **架构**：单体后端。`PipelineConfig` 硬编码四产线算子链（顺序 / 端口 / 参数映射 / 环节↔算子映射，meta 线 4 算子对 3 环节）；`TaskOrchestrator`（虚拟线程）执行：批次文件打 zip → `uploadFile(uniqueId=taskId_batchId)` → 按序 `predict`（中段 inputFile 原样透传，末位 `isLastOperator=true`，图文线带 `category`，透传任务级阈值/并发）→ 逐跳写 `task_stage_run`（summary / skipped / failed / code）→ 末位 stage zip 解包：`records.jsonl`→数据集明细行、`review.jsonl`→自动建复核单、lineage 存档 → 状态流转（有问题→待复核，无→待归集，批次失败→待处理）→ `removeFile` 清素材。
2. **产物访问**：平台与算子共享 `op-runtime` 卷；文件服务按任务授权读取（原图 / 裁切图 / visual 框图 / 页图 / PDF / HTML / trace.jsonl），防路径穿越。
3. **复核**：复核单 CR 编号；条目含 code 分类码 + 原因文本；A/B/C 留痕（改前改后 / 操作人 / 时间），暂存不闭环、整单提交闭环、任一结论后阈值锁定；重跑环节→未闭环旧单作废（void 留痕）；结论回写明细行 reviewStatus / revisionStatus。
4. **数据集**：归集生成候选版本（条数=总数−跳过−C 剔除；语义版本 V1.0 直出 / V2.0 复核闭环 / V3.0 起每重跑+1）；发布校验复核全闭环；仅已发布可下载 TXT 质量报告并登记交付记录；回滚需原因必填。
5. **ID**：雪花主键不外露；业务编号 TASK / DS / CR / 产线前缀（批次、交付、回滚）+ yyMMdd + 6 位 31 字符集 CSPRNG，唯一约束碰撞重试。
