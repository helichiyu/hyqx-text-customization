# 前后端对接说明 · 文本定制化生产算子服务

> 读者：平台侧前后端开发。本文回答三件事——**分工边界**（谁做什么）、**怎么部署**（docker compose 一键起 11 个算子）、**怎么调用**（三接口契约 + 四条产线编排 + 可直接跑的调用示例）。
> 字段级细节（每算子的输入输出、参数、数据集行样例）见同目录 `docs/` 下各算子说明书；本文只讲对接所需的最小集合。

---

## 1. 分工边界

| 侧 | 职责 |
| --- | --- |
| **算法侧（我们，已交付）** | 11 个算子服务（算法实现 + HTTP 接口 + Docker 部署件 + 样本 + 单测 + 说明书/测试指令）；四条产线的加工能力全部封装在算子内 |
| **后端（你们）** | ① 任务编排：按产线顺序调 predict，管 uniqueId / inputFile / isLastOperator 传递；② 素材管理：上传素材打包 zip → uploadFile，任务结束 removeFile；③ 复核流：消费 review.jsonl / reviewStatus，生成复核单，回流 revisionStatus，环节重跑时作废旧复核单；④ 归集：消费阶段 zip / records.jsonl 入库；⑤ 失败重试与任务状态机 |
| **前端（你们）** | 任务创建页（图文融合线需要选**任务大类**：几何/统计/表格/示意，透传给 predict 的 `category`）；进度展示（每步 predict 的 summary 计数）；复核工作台（review 行 + 版面线的 visual/ 框选图层 + 公式线 trace.jsonl 回溯字段）；数据集结果展示 |

一条产线跑完的形态：**素材 zip → 若干次 predict → 阶段 zip（含 records.jsonl 主成果 + review.jsonl + 血缘）**，之后进你们的复核与归集。

## 3. 部署

```bash
# 1) 解压全部算子 zip 到同名目录
for f in *.zip; do unzip -q "$f" -d "${f%.zip}"; done

# 2) 起服务（首次会构建镜像）
docker compose up -d --build

# 3) 验证（11 个全部回 code=0 即就绪）
for p in $(seq 6301 6311); do curl -s http://127.0.0.1:$p/healthz; echo; done
```

**端口映射**（容器内统一 6288，宿主机按算子分配）：

| 端口 | 算子 | 产线 | | 端口 | 算子 | 产线 |
| --- | --- | --- | --- | --- | --- | --- |
| 6301 | meta_clean_slice | 文本元信息① | | 6307 | fml_formula_locate | 公式文本① |
| 6302 | meta_genre_judge | 文本元信息① | | 6308 | fml_formula_recognize | 公式文本②③ |
| 6303 | meta_fact_extract | 文本元信息② | | 6309 | img_region_locate | 图文融合① |
| 6304 | meta_field_fill | 文本元信息③ | | 6310 | img_type_classify | 图文融合① |
| 6305 | lay_page_render | 复杂版面① | | 6311 | img_struct_describe | 图文融合②③ |
| 6306 | lay_page_detect | 复杂版面②③ | | | | |

部署注意：

- **共享数据卷**：compose 把宿主机 `./op-runtime` 挂到所有容器的 `/data`。链路传输要求下游容器能读到上游的 `outputFile`，统一挂载路径即可满足（路径闸门只放行 INPUT_DIR/OUTPUT_DIR 之内）。
- **出网**：8 个算子调硅基流动公网 API（key 已内置），宿主机需可出网；走内网网关时改 compose 中 `SILICONFLOW_BASE_URL` / `SILICONFLOW_API_KEY` 环境变量即可，无需改代码。
- **超时**：predict 是长任务（视觉算子约 15–25 s/样本，一整批分钟级）。编排侧 HTTP 客户端超时建议 **≥1800 s**，按异步任务处理，不要同步阻塞用户请求。

## 4. 三接口契约（11 个算子完全一致）

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/healthz` | GET | 就绪探针，回 `{"code":0,...,"data":{"operator":"中文名"}}` |
| `/uploadFile?uniqueId=<任务id_批次id>` | POST | 上传素材 zip（multipart 字段名 `file`）；流式落盘 ≤2GB；解压抹平层级；**同一 uniqueId 重传会先清空旧素材** |
| `/removeFile?uniqueId=` | POST | 幂等删除输入素材（重复调回 code=0） |
| `/predict` | POST | 一次性调用，请求体 JSON，见下 |

**/predict 请求体**：

```json
{
  "uniqueId": "t100_b01",            // 阶段首必传（取 uploadFile 的素材）；中段不传
  "inputFile": "<上一跳 outputFile>", // 链路中段必传；只接受本算子 OUTPUT_DIR/INPUT_DIR 之内的路径（含上游阶段 zip）
  "isLastOperator": true,            // 产线末位传 true：输出收口为 <run_id>_stage_output.zip
  "...算子参数": "..."                // 见 §8 参数速查表；不传用默认值
}
```

**成功响应（统一信封）**：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "outputFile": "/data/outputs/meta_field_fill_run_xxx/_stage_output.zip",
    "lineageFile": "/data/outputs/meta_field_fill_run_xxx/lineage_run_xxx.jsonl",
    "summary": { "total": 5, "matched": 2, "skipped": 3 },
    "skipped": [ { "name": "chart_001", "reason": "大类不一致（任务=几何，实判=统计）", "code": "category_mismatch" } ],
    "failed":  [ { "name": "doc_x.pdf", "reason": "PDF 已加密，无法打开", "code": "pdf_encrypted" } ]
  }
}
```

**失败响应**：业务失败一律 `code=1` + 中文原因，**HTTP 状态仍 200**（网络层 5xx 才是非 200）。编排侧按 code 分流即可，不要按 HTTP 状态码判断成败。

## 5. 四条产线编排（后端按此顺序调 predict）

```text
文本元信息： 6301 meta_clean_slice ─→ 6302 meta_genre_judge ─→ 6303 meta_fact_extract ─→ 6304 meta_field_fill【收口】
复杂版面：   6305 lay_page_render ──→ 6306 lay_page_detect【收口】
公式文本：   6307 fml_formula_locate → 6308 fml_formula_recognize【收口】
图文融合：   6309 img_region_locate → 6310 img_type_classify ─→ 6311 img_struct_describe【收口】
```

传递规则只有三条：

1. **阶段首**（6301/6305/6307/6309）：先 `uploadFile` 上传素材 zip，`predict` 传 `{"uniqueId": "..."}`；
2. **中段**：`predict` 传 `{"inputFile": "<上一跳响应的 data.outputFile>"}`——原样透传，不要改写路径；
3. **末位**：加 `"isLastOperator": true`，响应的 outputFile 是阶段 zip，交复核/归集。图文融合线判型（6310）必须带 `"category"`。

## 6. 完整调用时序（文本元信息线为例）

```bash
UID=t100_b01

# 1) 上传素材（阶段首）
curl -X POST "http://127.0.0.1:6301/uploadFile?uniqueId=$UID" -F "file=@meta_samples.zip"

# 2) 正文抽取与切片（凭 uniqueId）
curl -X POST http://127.0.0.1:6301/predict -H "Content-Type: application/json" \
  -d "{\"uniqueId\":\"$UID\"}"
# → data.outputFile = /data/outputs/meta_clean_slice_run_xxx/（记为 OUT1）

# 3) 体裁判定（凭 inputFile 接续）
curl -X POST http://127.0.0.1:6302/predict -H "Content-Type: application/json" \
  -d "{\"inputFile\":\"$OUT1\"}"

# 4) 事实抽取 → 5) 三组补全（末位收口）
curl -X POST http://127.0.0.1:6303/predict -H "Content-Type: application/json" \
  -d "{\"inputFile\":\"$OUT2\"}"
curl -X POST http://127.0.0.1:6304/predict -H "Content-Type: application/json" \
  -d "{\"inputFile\":\"$OUT3\",\"isLastOperator\":true}"
# → data.outputFile = /data/outputs/..._stage_output.zip（阶段产物）

# 6) 任务结束后清理素材（幂等）
curl -X POST "http://127.0.0.1:6301/removeFile?uniqueId=$UID"
```

**可直接跑的示例**：`python chain_example.py meta`（另有 lay / fml / img，img 带大类参数如 `python chain_example.py img 统计`）——上传包内样本、按序走完一条产线、打印每步 summary 与跳过/失败明细。联调时建议先用它打通，再接你们自己的编排。

## 7. 结果路由：skip / review / failed（后端复核与归集消费）

| 去向 | 载体 | 语义 | 编排动作 |
| --- | --- | --- | --- |
| skipped | 响应 `data.skipped[]`（name + 中文原因 `reason` + 机器码 `code`） | 素材不适用（导航页/非新闻/大类不一致/空白页/整份 0 公式等） | **不再传下游**；同批其它样本继续 |
| review | 输出目录 `review.jsonl`（整行记录 + reviewReason + code）；数据集行 `reviewStatus=待复核` | 低置信 / 候选冲突 / 输出经修复等，需人工裁定 | **照常传下游**（数据集行保留）；复核工作台展示 |
| failed | 响应 `data.failed[]`（name + reason + code） | 处理失败（加密 PDF / 模型持续失败等） | 该样本出局；按你们的重试策略处理 |

复核约定要点：

- `reviewReason` / `skipped.reason` / `failed.reason` 是**面向复核员的中文文本**；分类与统计一律用同条目的 `code`（小写下划线机器码，如 `low_confidence`、`model_call_failed`、`category_mismatch`、`pdf_encrypted`），不要解析中文。复核记录里 `triggerCode` 直接取该字段即可。
- `code` 是封闭枚举：新增取值随算子版本发布同步给平台，平台对未知 `code` 按 `unclassified` 兜底展示；同一行命中多个条件时按算子内优先级只取一个码。
- 复核修订后把结论写到数据集行的 `revisionStatus`（人工修订/维持原判等，由你们定义），`reviewStatus` 的流转（待复核→已复核）也由平台维护——算子只在产出时写初始状态。
- 版面线复核可看 `visual/*.png`（页图+检测框）；公式线回溯字段在 `trace.jsonl`（页码/bbox/裁切图路径）；元信息线逐字段置信度在 `fields_detail.jsonl`。
- **环节重跑**：重跑某算子会产生新 run 目录（旧产物不覆盖）；旧复核单作废由平台侧管理。

## 8. 各算子 /predict 参数速查（不传用默认值）

| 算子 | 参数（括号内为默认值） |
| --- | --- |
| meta_clean_slice | 无（切片 2000/重叠 200 为固定口径，不开放覆盖） |
| meta_genre_judge | confidence_threshold(0.8)、concurrency(4) |
| meta_fact_extract | confidence_threshold(0.8)、concurrency(4) |
| meta_field_fill | confidence_threshold(0.8)、max_text_chars(6000)、concurrency(4) |
| lay_page_render | dpi(150，72–300)、image_format(png) |
| lay_page_detect | confidence_threshold(0.8)、iou_threshold(0.3)、concurrency(4)、draw_overlay(true) |
| fml_formula_locate | dpi(150)、max_context_chars(2000)、concurrency(4) |
| fml_formula_recognize | confidence_threshold(0.8)、concurrency(4) |
| img_region_locate | border_tolerance(18)、min_crop_size(32) |
| img_type_classify | **category（必填：几何/统计/表格/示意）**、confidence_threshold(0.8)、concurrency(4) |
| img_struct_describe | confidence_threshold(0.8)、concurrency(4) |

阈值类参数（confidence_threshold 等）是任务级可调项，建议做成任务配置透传；切片 2000/200、IoU 0.3、上下文 2000 字、重试 2 次是固定口径不开放。

## 9. 对接注意事项（踩坑清单）

1. `uniqueId` 按「任务id_批次id」生成，只含字母数字下划线连字符；重传同名会**清空旧素材**。
2. `inputFile` 必须原样传上一跳的 `data.outputFile`——算子有路径闸门，传任意路径会拒（code=1）。
3. 跨产线不要混传：每条产线的 inputFile 必须来自本产线上一跳。
4. 图文融合线：任务创建时前端必须选大类，predict 判型环节带 `category`；大类不一致的图会被跳过（原因里带任务大类与实判大类）。
5. predict 为长任务：客户端超时 ≥1800 s；同一算子服务可被多任务并发调用（算子内部已限并发 4–8）。
6. 业务失败 HTTP 仍 200，按信封 `code` 分流；`skipped`/`failed` 数组条目自带 `code` 机器码用于分类，中文 `reason` 可直接入库展示。
7. 各算子返回的 `summary` 字段结构略有差异（如 meta 线 total/passed、图文线 total/matched），进度展示建议按 key 透传展示，不硬编码。
8. 输出目录按 run 递增不覆盖：归集取阶段 zip 即可，中间产物是否清理由平台策略定（清理时只动 `op-runtime/outputs`，输入素材用 removeFile）。
