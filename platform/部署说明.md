# 文本定制化生产平台 · 部署说明

> 适用版本：平台端 `wbdz-server 1.0.0` + `wbdz-web`（2026-11 交付）
> 阅读顺序：先看第 1 节拓扑，再按第 3 节逐项部署；第 7 节列出**必须由甲方确认后才能定稿**的环境项。

---

## 1. 部署拓扑

单机部署（推荐交付形态）：

```
                ┌──────────────────── 浏览器 ────────────────────┐
                │                 http(s)://<域名>/              │
                └───────────────────────┬───────────────────────┘
                                        │
                              ┌─────────▼─────────┐
                              │  Nginx            │  静态资源 dist/ + /api 反代
                              └─────────┬─────────┘
                                        │ 127.0.0.1:8090
                              ┌─────────▼─────────┐
                              │ wbdz-server       │  Spring Boot 3.5 / Java 21
                              │ (JWT / 编排 / 复核)│
                              └───┬───────────┬───┘
                    JDBC 3306     │           │ HTTP 6301–6311
                      ┌───────────▼──┐   ┌────▼──────────────────────────┐
                      │ MySQL 8      │   │ 11 个算子服务（Docker 或进程） │
                      │ wbdz_platform│   │ 6301…6311                     │
                      └──────────────┘   └────┬──────────────────────────┘
                                              │ 读写共享目录
                                     <op-runtime>/input、/output
```

- 平台与算子**必须共享同一个产物目录**：算子在容器内写 `/data/input`、`/data/output`，
  平台侧通过 `WBDZ_OP_RUNTIME_DIR` 指向宿主机上与之对应的目录（Docker 部署时为挂载点）。
- 后端无状态（除本地落盘的上传素材与产物目录），可单实例部署；暂不支持多实例共享同一落盘目录。

## 2. 环境要求

| 项 | 最低 | 建议 |
| --- | --- | --- |
| 操作系统 | Linux x86_64（Ubuntu 22.04 / CentOS 7+）或 Windows Server | Linux |
| CPU | 8 核 | 16 核（算子含视觉模型调用，主要耗时在网络侧） |
| 内存 | 16 GB | 32 GB |
| 磁盘 | 200 GB | 500 GB（素材、阶段 zip、数据集产物持续累积） |
| JDK | 21（运行后端） | Temurin 21 |
| MySQL | 8.0 | 8.0，独立账号 + 定时备份 |
| Node.js | 18（**仅构建前端时需要**） | 20 LTS |
| Docker | 24+（若算子用容器部署） | 与 compose v2 |
| 网络 | 能访问 `api.siliconflow.cn:443`（或甲方内网模型网关） | 固定出口 IP 便于加白 |

端口占用：

| 端口 | 用途 | 暴露范围 |
| --- | --- | --- |
| 80/443 | Nginx（前端 + `/api`） | 对外 |
| 8090 | 后端 | 仅本机 / 内网 |
| 3306 | MySQL | 仅本机 / 内网 |
| 6301–6311 | 算子 | 仅本机（容器内网也可） |

> 若算子端口需要调整，同步修改后端 `application.yml` 的 `wbdz.operator-ports` 映射，
> 该映射是算子 tag → 宿主机端口的唯一来源，不要只改 compose。

## 3. 部署步骤

### 3.1 数据库

```sql
CREATE DATABASE wbdz_platform DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'wbdz'@'%' IDENTIFIED BY '<强密码>';
GRANT ALL PRIVILEGES ON wbdz_platform.* TO 'wbdz'@'%';
FLUSH PRIVILEGES;
```

建表与初始数据由后端启动时的 Liquibase 自动执行（`changelog-master.xml`），**不需要手工导 SQL**。
首次启动后确认 `DATABASECHANGELOG` 中有 14+ 条记录；重复启动不应重复执行。

初始账号 `admin / admin123` 由变更脚本写入，**上线后必须立即修改**（见 3.5）。

### 3.2 算子服务

**方式 A：Docker（推荐）**

```bash
cd release
for f in *.zip; do unzip -q "$f" -d "${f%.zip}"; done
docker compose up -d --build
```

- `review/` 下是 11 个算子包与 `docker-compose.yml`，端口 6301–6311，共享卷 `/data`。
- 模型密钥通过 compose 的 `environment` 注入（见 3.4），不要把密钥写进镜像。
- 健康检查：`curl http://127.0.0.1:6301/healthz` … `6311` 全部返回 `{"status":"ok"}`。

**方式 B：本地进程（无 Docker 环境）**

```bash
cd <项目根>
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r operators/requirements.txt    # 或按各算子 requirements
export INPUT_DIR=/data/input OUTPUT_DIR=/data/output
for pair in meta_clean_slice:6301 ... img_struct_describe:6311; do
  tag=${pair%%:*}; port=${pair##*:}
  (cd operators/$tag && INPUT_DIR=/data/input OUTPUT_DIR=/data/output PORT=$port \
     nohup python -I -m uvicorn inference:app --host 127.0.0.1 --port $port \
     >> /var/log/wbdz/$tag.log 2>&1 &)
done
```

注意：`INPUT_DIR/OUTPUT_DIR` 必须以 `/data` 开头（算子契约），服务进程的当前盘根下
会实际生成 `data/input`、`data/output`；平台 `WBDZ_OP_RUNTIME_DIR` 指向同一个 `data` 目录。

### 3.3 后端

```bash
cd platform/wbdz-server
mvn -DskipTests clean package
# 产物 target/wbdz-server-1.0.0.jar
```

systemd 示例（`/etc/systemd/system/wbdz-server.service`）：

```ini
[Unit]
Description=WBDZ Platform Server
After=network.target mysql.service

[Service]
User=wbdz
WorkingDirectory=/opt/wbdz
Environment=JAVA_HOME=/usr/lib/jvm/temurin-21-jdk
Environment=WBDZ_DB_HOST=127.0.0.1
Environment=WBDZ_DB_PORT=3306
Environment=WBDZ_DB_USER=wbdz
Environment=WBDZ_DB_PASSWORD=<强密码>
Environment=WBDZ_JWT_SECRET=<32 字节以上随机串>
Environment=WBDZ_STORAGE_DIR=/data/wbdz/storage
Environment=WBDZ_OP_RUNTIME_DIR=/data
Environment=SILICONFLOW_API_KEY=<如算子与后端同机注入>
ExecStart=/usr/lib/jvm/temurin-21-jdk/bin/java -Xms1g -Xmx4g -jar /opt/wbdz/wbdz-server-1.0.0.jar
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now wbdz-server
curl http://127.0.0.1:8090/api/healthz
```

`WBDZ_STORAGE_DIR` 与 `WBDZ_OP_RUNTIME_DIR` 必须是**持久化磁盘**并纳入备份；
这两个目录不在 jar 内，换机/升级时需整体迁移。

### 3.4 模型密钥与网关

配置位置：每个算子包内 `<算子>/<算子>/utils/llm_config.py`，运行时读取环境变量覆盖默认值。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `SILICONFLOW_API_KEY` | 内置联调密钥 | 生产必须通过环境变量/compose 注入，并轮换 |
| `SILICONFLOW_BASE_URL` | `https://api.siliconflow.cn/v1` | 若甲方有内网网关或代理，改这里即可，无需改代码 |
| `VISION_MODEL` | `Qwen/Qwen3-VL-32B-Instruct` | 视觉类算子 |
| `TEXT_MODEL` | `deepseek-ai/DeepSeek-V3.2` | 文本类算子 |

要求：

1. **密钥不入库、不进镜像、不写前端**；交付前把内置密钥视为已泄露并轮换。
2. 甲方若不允许出公网：提供 OpenAI 兼容网关地址，设置 `SILICONFLOW_BASE_URL`，
   并保证 11 个算子容器/进程都能访问该地址。
3. 模型调用超时与重试在算子内部（默认 3 次退避），平台侧不再二次重试。

### 3.5 前端与 Nginx

```bash
cd platform/wbdz-web
npm ci
npm run build          # 产出 dist/
```

Nginx 示例：

```nginx
server {
    listen 80;
    server_name _;
    root /opt/wbdz/web/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;   # 前端 history 路由
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8090/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        client_max_body_size 200m;           # 素材支持 ZIP，按最大上传调整
        proxy_read_timeout 300s;             # 上传/校验/报告下载
    }
}
```

上线检查：

- `http://<域名>/` 可登录；
- 登录后修改 `admin` 密码（或在数据库把 `admin123` 替换为 BCrypt 值后重启）；
- 若启用 HTTPS，在 Nginx 层终止 TLS，后端保持 HTTP 内网访问。

### 3.6 上传大小与素材限制

素材准入规则由参数配置中心管理（全局参数组），默认单文件 ≤50 MB、图片分辨率 ≥600、PDF 可渲染、
HTML 去标签 ≥20 字。Nginx `client_max_body_size` 必须 ≥ 前端允许的 ZIP 体积。
后端对上传文件名做 `businessId_原名` 落盘，路径穿越在存储层与产物代理层双重校验。

## 4. 配置项清单

后端全部配置见 `platform/wbdz-server/src/main/resources/application.yml`，可用环境变量覆盖：

| 变量 | 默认 | 必改 |
| --- | --- | --- |
| `WBDZ_DB_HOST` / `WBDZ_DB_PORT` | `127.0.0.1` / `3306` | 视环境 |
| `WBDZ_DB_USER` / `WBDZ_DB_PASSWORD` | `root` / `wbdz123` | **是** |
| `WBDZ_JWT_SECRET` | 内置开发密钥 | **是** |
| `WBDZ_JWT_EXPIRE_HOURS` | `72` | 按安全策略 |
| `WBDZ_STORAGE_DIR` | `./wbdz-storage` | **是**（持久化路径） |
| `WBDZ_OP_RUNTIME_DIR` | `./op-runtime` | **是**（与算子共享） |
| `WBDZ_OPERATOR_BASE` | `http://127.0.0.1` | 算子不在本机时 |
| `wbdz.operator-ports` | 6301–6311 | 端口调整时 |

其他运行参数（阈值、并发数、素材准入）在**平台参数配置页**维护并发布版本，
不需要改配置文件；任务创建时锁定当时的参数快照。

## 5. 数据与备份

| 数据 | 位置 | 备份建议 |
| --- | --- | --- |
| 业务数据 | MySQL `wbdz_platform` | 每日全备 + binlog，保留 30 天 |
| 上传素材 | `WBDZ_STORAGE_DIR` | 每日增量，与数据库同批次 |
| 算子产物 | `WBDZ_OP_RUNTIME_DIR/input、output` | 可再生成部分按需保留；数据集发布物建议长期保留 |
| 日志 | 后端 stdout / 算子日志 | 按 30 天轮转，避免占满磁盘 |

恢复顺序：MySQL → 素材目录 → 产物目录 → 启动后端（Liquibase 校验 checksum，不重跑历史变更）。

## 6. 验收与健康检查

| 检查 | 命令 / 动作 | 期望 |
| --- | --- | --- |
| 后端存活 | `curl :8090/api/healthz` | 200 |
| 算子存活 | `curl :6301…6311/healthz` | 11 个 200 |
| 登录 | 页面 `admin` 登录 | 进入工作台 |
| 全链路 | 素材上传 → 校验 → 移交 → 建任务 → 启动 → 待复核 → 闭环 → 归集 → 发布 → 报告下载 | 四产线各一条 |
| 数据落盘 | 数据库记录 + `WBDZ_STORAGE_DIR` 文件 | 一致 |
| 幂等 | 重启后端 | Liquibase 不重复执行，历史数据不丢 |

仓库内 `platform/scripts/e2e_lines.py`、`e2e_finish.py`、`e2e_regress.py` 可用于部署后自动冒烟
（脚本默认连 `127.0.0.1:8090`，需在部署机跑或改 `BASE`）。

## 7. 甲方环境待定项（部署前必须确认）

| # | 待确认项 | 影响 | 默认/建议 |
| --- | --- | --- | --- |
| D1 | 服务器规格与操作系统、是否允许 Docker | 算子部署方式（compose / 进程 / systemd） | 16C/32G Linux + Docker |
| D2 | 对外域名、是否 HTTPS、证书来源 | Nginx 配置与前端 `base` | 甲方提供域名；无则内网 IP |
| D3 | 是否允许访问公网 `api.siliconflow.cn` | 模型调用方式 | 若不允许，甲方提供 OpenAI 兼容内网网关 |
| D4 | 模型 API Key 的提供与轮换责任人 | 密钥注入与合规 | 甲方提供正式 key，平台侧只用环境变量 |
| D5 | 数据库由甲方托管还是随平台部署 | 连接参数、备份责任 | 建议独立 MySQL 8 实例 |
| D6 | 数据保留期限与备份策略 | 磁盘规划、清理任务 | 素材/产物保留 ≥1 年 |
| D7 | 并发任务量与单批素材规模 | 线程/内存/超时参数 | 按首批试运行数据再调 |
| D8 | 是否要求统一身份（LDAP/OIDC） | 当前为本地账号 + JWT | 首版单角色 `admin`，后续可扩展 |

在上述项确认前，平台按第 3 节单机默认配置即可完整运行；D3/D4 变化只涉及环境变量，不改代码。

## 8. 已知边界与回退

1. **本次未做 Docker 全栈一键 compose**：按项目确认，平台侧验证采用“本机 MySQL + 本地算子进程 + 本地后端/前端”方式；算子交付包自带的 `release/docker-compose.yml` 可直接用于 11 个算子。若甲方要求平台也容器化，需额外提供 `wbdz-server` / `wbdz-web` 的 Dockerfile 与全栈 compose（约 0.5 人日）。
2. **单实例**：上传素材与产物落在本机目录，暂不支持多后端实例共享；横向扩展需先引入对象存储。
3. **模型质量**：语义指标（情感一致率、主题相关率等）为**模型盲评**结果，不是人工判定，报告中已注明口径；不达标样本通过复核 B/C 与重跑处理。
4. **回退**：升级前备份数据库与两个数据目录；回退时恢复备份并回退 jar/dist 版本，Liquibase 历史 changeSet 不修改。
